# Character Editor

Редактор персонажей для glTF/VRM моделей (тестовая — `female_base.vrm`, VRoid Studio).
C++17, OpenGL 3.3 core, Dear ImGui. Windows / MinGW.

## Сборка и запуск

```powershell
cmake -S . -B build -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
.\build\character_editor.exe                      # интерактивный режим (из корня репо!)
.\build\character_editor.exe --frames 30 --screenshot shot.png   # пакетный режим
```

Пути `female_base.vrm`, `config/`, `presets/`, `models/` относительные, но при старте
`ensureDataRoot()` ищет `config/body_params.json`, поднимаясь от пути exe (и от cwd) вверх
до 5 уровней, и переключает туда cwd — двойной клик по exe тоже находит конфиги/пресеты/models.

CLI: `[model] [--model p] [--preset name] [--screenshot out.png] [--frames N] [--size WxH]`
`[--set id=value]... [--yaw deg] [--dist m] [--targety m] [--clothe path]... [--listparams]`.
Файлы .vrm/.glb/.gltf можно перетаскивать в окно; кнопки «Открыть модель...» / «Добавить одежду...»
открывают стандартный диалог проводника (GetOpenFileName, у одежды — multiselect).

## Архитектура

- `src/core/` — `Math3D.h` (vec/quat/mat, column-major), `GL.{h,cpp}` (свой загрузчик GL-функций через `glfwGetProcAddress`, без glad/glew).
- `src/model/` — `Model.h` (рендер-независимые данные), `GltfLoader` (tinygltf; .vrm/.glb определяются по магии `glTF`), `Skeleton` (мировые матрицы узлов, per-node scale+translate offsets).
- `src/editor/` — `ShapeController` (параметры тела/лица/морфов), `Presets` (JSON в `presets/`).
- `src/clothing/` — `ClothingManager`: автоподгонка и автоскиннинг одежды (см. ниже).
- `src/render/` — `Shader`, `Camera` (орбитальная), `ModelRenderer` (мульти-модель по слотам:
  слот 0 = тело, остальные = одежда; GPU-скиннинг до 80 костей; проходы: контур → opaque/mask →
  blend; sRGB; флаги волос `hideHair`/`hairTint`). **Аниме-рендер**: тун-шейдинг в `kModelFS`
  (2 мягко-квантованные полосы через `fwidth`, холодный оттенок тени `vec3(0.66,0.64,0.78)`,
  rim-свет по освещённой стороне; `uToon`) и inverted-hull контур (`kOutlineVS/FS`: выдавливание
  по проецированной нормали на постоянную экранную толщину в px через `uWinSize`, цвет контура ×
  альбедо, alpha-test как у основного прохода, blend-примитивы пропускаются, рисуется с
  `glCullFace(GL_FRONT)` до основных проходов). Управление — вкладка «Вид» («Тун-шейдинг»,
  «Контур», толщина px), флаги в `ModelRenderer`: `toonShading`, `outlineEnabled`, `outlineWidth`,
  `outlineColor`.
- `src/ui/` — `EditorUI` (левая панель 340px, вкладки сверху как в VRoid: **Тело | Лицо | Причёска | Одежда | Пресеты | Вид**, контент вкладок — прокручиваемый child-регион, шапка/подвал закреплены; русский UI, кириллица из segoeui/arial).
- `src/app/` — `Application` (окно GLFW, цикл, drag&drop, скриншоты, инвалидация облака одежды), `FileDialog` (Win32 GetOpenFileNameW).

## Параметры тела и лица

Правила в `config/body_params.json` (точные имена + regex-паттерны для других моделей);
без файла — встроенные правила. Значение нормировано 0..1, масштаб = lerp(min,max),
по осям — `pow(s, axisExp)`. Два формата правил:
- плоский (`bones/patterns/axes/compensate` на верхнем уровне);
- `entries`: несколько правил на параметр, у каждого свои axes; `translate` — смещение кости
  (`mode: value` → `axis*factor*(v-def)`, `mode: scale` → `axis*factor*(s-1)`).

Вкладка «Тело» рисует bone-параметры сворачиваемыми секциями по `p.group`: «Фигура»
(`breast_size`, `buttocks_size`, `hip_width`, `waist_size`, `weight` (hips+spine+chest+бедра+плечи;
у spine повышенный отклик X/Z `[1.5,0.4,1.3]` — талия расширяется сильнее груди/бёдер),
`belly_abs`), «Рост» (`height` — ноги+спина по Y + подъём hips на `0.78*(s-1)`, чтобы ступни
оставались на полу, `leg_length`, `arm_length`, `torso_length` — spine+chest по Y, compensate,
ступни и так на месте, подъём не нужен), «Мышцы»: `muscle_arms`
(плечо+предплечье по Y/Z, кисти компенсированы), `muscle_legs` (бедро+голень по X/Z, ступни
компенсированы), `muscle_shoulders` (дельты, без compensate — рука наследует масштаб по цепочке),
`muscle_chest` (грудная клетка по X/Z, compensate — bust/шея/плечи не меняют размер, только
позиции). Голова: `head_size` (кость). Компенсация (`compensate:true`) — дочерним костям
обратный масштаб (ягодицы не растягивают торс); потомки, сами являющиеся целями того же правила,
не компенсируются (поэтому бедро+голень можно держать в одном правиле).

**Вершинные эффекторы (редактор сосков)** — `ShapeParam::Type::VertexEffect`, секции
`effectorAnchors`/`effectorParams` в `body_params.json`. Якорь = bust-кость (`J_Sec_*_Bust1`);
apex (сосок) = bust-взвешенная вершина, ближайшая к кончику цепочки (`Bust2`, первая дочерняя
кость из joints скина). Скин якоря выбирается по «владеет ли скин вершинами с весом на кость»
(bust есть в скинах лица И тела — первый не подходит). Деформация: гауссовы купола в bind-space
(`exp(-(d/r)²)` смещение по нормали + градиентная поправка нормали), идемпотентно (перезапись из
сохранённых bind-баз — mesh без морфов не пере-блендится), вызывается после morph re-blend +
`reupload`. Параметры (в метрах, значение 0..1 → lerp(min,max)): `nipple_length` (купол r=tipR),
`nipple_width`, `areola_size`, `areola_bulge` (купол r=areolaR), `areola_tint` (0..1, только
шейдер). Одежда на бамп не реагирует (подгонки к поверхности нет), но бамп масштабируется
вместе с грудью (GPU-скиннинг bust-кости). Тинт ореолы — в `kModelFS` (`uAreolaPos[2]` — мировые
позиции apex через joint-матрицу, smoothstep по `uAreolaRadius`, умножение альбедо на
`uAreolaColor`, только слот тела `forceSkin<0`; цвет — UI «Цвет ореолы» на вкладке «Тело»).

**Редактор лица (глаза/нос/рот) — региональные деформеры** — `ShapeParam::Type::VertexDeform`,
секции `deformAnchors`/`deformParams` в `body_params.json`. Якорь (`buildDeformAnchors`) = позиция
кости в бинде (`bones`/`patterns`, напр. `J_Adj_*_FaceEye`), центроид вершин примитивов с материалом
по regex (`material` — рот = FaceMouth) или крайняя по направлению вершина (`extreme` — нос = самая
передняя точка skin-примитива). В радиусе 9 см от якоря собираются вершины ВСЕХ примитивов (кроме
волос) — iris/white/highlight/eyeline/skin движутся совместно, поэтому зрачки не отрываются от глаз
(раньше глазные параметры были костными по `J_Adj_*_FaceEye` и рвали радужку: у примитивов глаза
разные веса на эту кость; костные eye_* удалены из конфига). Деформация в bind-space с гауссовым
falloff (`radius` на параметр): `translate` (сдвиг по оси; per-anchor оси для зеркальности),
`scale` (масштаб вокруг якоря, `axis` — маска осей), `protrude` (по нормали якоря). Применяется
**аддитивно поверх морф-бленда** в `applyEffectorsToMesh`; нейтраль: scale=1, translate/protrude=0
(пропуск без дельты). Идемпотентность: дельты накапливаются по вершинам и применяются один раз —
морфовые примитивы (лицо) получают `+=` поверх свежего бленда (он сбрасывает `blendedPos` каждый
проход), а НЕморфовые (тело: шея/челюсть попадают в радиус глазных якорей) — перезапись из `pos`
(бленд их `blendedPos` НЕ сбрасывает — простой `+=` накапливал дрейф при каждом движении слайдера,
шов голова/тело «отслаивался»). Вкладка «Лицо»:
секции «Глаза»/«Нос»/«Рот» (деформеры, открыты), «Голова» (`head_size`), группы морфов-эмоций.
Пресеты хранят по id — старые значения `eye_*` подхватываются новыми параметрами.

## Одежда (статические меши без скелета)

Пайплайн (`ClothingManager`):
1. Загрузка + запечка node-трансформов в вершины.
2. **Авто-единицы**: диагональ bbox → кандидаты {100..0.0001}, правдоподобие 0.25..2.3 м
   (mm/cm/dm Sketchfab-модели).
3. **Позиционирование (детерминированное, без итеративного поиска)**: тип одежды → якорь
   из `config/clothing_types.json` («тип → высота на теле»: трусы 0.92, штаны 0.52, юбка 0.8,
   топ 1.22, обувь — низ bbox на 0…; `auto`/`accessory` — авторская посадка как есть).
   Якорь центрирует X/Z по оси тела и двигает bbox на `yOffset`. **Масштаб не трогается** —
   размер подгоняет пользователь (гизмо/слайдер), пресеты его хранят (авто-подбор ширины
   по телу удалён: рукава/бретели в T-позе ломали замер). Якоря редактируются в UI и
   сохраняются в конфиг.
4. **Тип одежды**: авто-детект по ключевым словам пути файла (top+bottom ключевые вместе =
   комплект → `auto`). Тип определяет **слот**: top/bra→Верх, panties/shorts/pants/skirt→Низ,
   dress→Платье, shoes→Обувь, head→Причёска, accessory→Аксессуар; у `auto` слота нет.
   Надевание (`Application::wearClothing` — каталог и файловый диалог) снимает прежний
   предмет слота (после успешной загрузки нового).
5. **Каталог** (`ClothingCatalog`): рекурсивный скан `models/` на .gltf/.glb/.vrm
   (текущая модель тела исключена по имени файла), имя = родительская папка для
   Sketchfab-«scene.gltf», тип/слот детектятся при скане. UI «Каталог» на вкладке
   «Одежда»: группы по слотам, клик = надеть, кнопка «Обновить» = перескан.
6. **Перенос весов (привязка к скелету, БЕЗ деформации меша)**: каждая вершина одежды
   (в её текущем трансформе) получает inverse-square смесь весов K=4 ближайших точек
   облака тела (spatial hash 5 см, точный expanding-ring с early-out). Меш одежды
   **никогда не деформируется** — форма всегда авторская, порваться/схлопнуться не может
   (раньше тут была клэмп-подгонка к поверхности: wrap-deformer BVH, драп-конверт,
   релаксация — всё удалено из-за неустранимых артефактов). Дальше одежда живёт на
   **GPU-скиннинге того же скелета**: все морфы тела — это масштаб/сдвиг костей, поэтому
   фигуру одежда повторяет автоматически в реальном времени, без рефитов. Просветы/
   пересечения при экстремальных формах — пользователь правит гизмо (принятый workflow).
   Облако тела **кэшируется и делится между всеми предметами** (`invalidateBody()` при
   смене тела/фигуры — влияет только на будущие bind-ы). Многопоточность с >4000 вершин.
7. **rebind / applyFit**: `rebind` — полный перенос весов в текущем трансформе (гизмо
   отпущен, слайдер отпущен, пресет загружен); `applyFit` — дешёвое обновление
   позиций/нормалей матрицей fit во время драга. Пресет без `fitOffset` — позиция
   берётся с якоря типа (`applyType`).

UI одежды: слоты (снять/выбрать), каталог, видимость, тип (якорь), Масштаб, Смещение,
«Вернуть на якорь», «Удалить».

**Gizmo** (`src/ui/Gizmo3D`, свой, без ImGuizmo): screen-space, рисуется через
`ImGui::GetForegroundDrawList`. Режимы — перемещение (3 оси + 3 плоскости), вращение (3 кольца),
масштаб (uniform, центральный квадрат). Цель — выбранный предмет (клик по имени в списке).
Во время драга вершины одежды трансформируются на CPU через `ClothingManager::applyFit`
(дешёвый: только матрица fit) + re-upload VBO; на отпускании — `rebind` (перенос весов
в новой позе). Камера блокируется, когда gizmo hover/drag; клики по ImGui-виджетам
не перехватываются (`io.WantCaptureMouse`). Поворот одежды хранится как `fitRot` (кватернион),
в пресете — `fitRot: [x,y,z,w]`.

## Ключевые решения / подводные камни

- **Скин тела ≠ самый большой меш**: у VRM лицо (+волосы) часто плотнее тела и имеет
  свой скин. `ClothingManager::bind` берёт скин меша с наибольшей ВЕРТИКАЛЬНОЙ протяжённостью
  (ноги..голова), иначе облако точек = одно лицо и перенос весов ломается.
- **Renderer хранит `Model*` внутрь `clothing_.items()`** — вектор переаллоцируется/сдвигается
  при add/remove → `ClothingManager::onItemsChanged` перепривязывает слоты (`setModel`).
- **JOINTS_0 у тела VRoid — float32** (не u16/u8) — читаем и такое.
- **mat3→quat для узлов с `matrix`** — следить за column-major индексами (Shepperd).
- Динамический VBO (pos+nrm) заполняется для ВСЕХ примитивов, не только морфовых.
- Производительность: staging-буфер в `uploadVertices` (без аллокаций на кадр), кэш локаций
  юниформов в `Shader`, гизмо ре-applies fit только при реальном изменении за кадр,
  облако тела кэшировано (`invalidateBody`), пресеты грузятся с `deferBind` (один rebind).
- Причёска: цвет/видимость (материалы с `hair` в имени) на вкладке «Причёска»;
  своя причёска = надевается из каталога (слот «Причёска», веса лягут на голову).
- Нормали одежды поворачиваются вслед за `fitRot` (в transferWeights/applyFit) — иначе
  ломается освещение после вращения гизмо.
- **Зеркальные node-трансформы** (отрицательный scale, det<0) — при запечке в
  `bakeNodeTransforms` переворачивается winding треугольников, иначе меш вывернут наизнанку.
- Ограничения: экстремальные формы (грудь ×1.8) могут не покрываться чужой одеждой
  (подгонки к поверхности нет — одежда растёт только со скиннингом костей; решается
  масштабом гизмо или более свободной моделью одежды); A-поза рукавов у источника vs
  T-поза тела; `COLOR_0`, spring bones не поддерживаются; MToon-параметры материалов
  не читаются — тун-шейдинг и контур свои, приближённые.
- Пресеты v2: `{"model", "values": {id: 0..1}, "clothing": [{path, fitScale, fitOffset,
  padding, shrink, looseness, visible, type, slot, fitRot}]}` — поля `padding/shrink/looseness`
  устарели (игнорируются при чтении, не пишутся); без `fitOffset` — позиция с якоря типа.
